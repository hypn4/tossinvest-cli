# Signals Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `tossctl signals list <sym>...` and `tossctl signals detail <sym>` commands that surface Toss's Korean-language AI reasoning, news headlines, related-stock graph, and scheduled event signals (실적 발표/공시) — the highest-density single endpoint for LLM context discovered in the order-page reverse engineering.

**Architecture:** Three new domain types (`Signal`, `SignalDetail`, `EventSignal`) → three new client methods (`ListSignals`, `GetSignalDetail`, `ListEventSignals`) → output formatters that render Korean narrative for humans and pass clean JSON for agents → `tossctl signals` cobra command tree. All three endpoints are **public** (`wts-info-api`), no certified API headers required.

**Tech Stack:** Go 1.x, cobra CLI, existing `internal/client.Client.getJSON` and `postJSON` helpers. JSON-only encoding; no streaming.

  - `.captures/2026-05-15/us-soxl/home-signals-v2.network-response` — event signals (실적 발표)

Three endpoints, three shapes:

1. `POST /api/v1/dashboard/wts/overview/ai-signals` body `{"productCodes":[...]}` → `.result.signals[].reasoningDescription` (≤25 chars Korean).
2. `GET /api/v1/dashboard/wts/overview/ai-signals/detail?productCode={code}&productType=STOCKS` → rich payload: `signalDirection` (1/-1), `reasoning.description.data[]` (3 bullets), `reasoning.news.data[]`, `reasoning.keywords[]`, `relatedReasoning.details[]` (related stocks).
3. `POST /api/v2/dashboard/wts/overview/signals` body `{"productCodes":[...], "filters":[]}` → scheduled event signals keyed by `signalId` (6000000-range = 실적 발표).

package client

import (
	"context"
	"encoding/json"
	"fmt"
	"net/url"
	"strings"
	"time"

	"github.com/junghoonkye/tossinvest-cli/internal/domain"
)

type signalsBatchEnvelope struct {
	Result struct {
		Signals []struct {
			ProductCode          string `json:"productCode"`
			ReasoningDescription string `json:"reasoningDescription"`
		} `json:"signals"`
	} `json:"result"`
}

// ListSignals returns one-line Korean reasoning per code in the input list.
// Toss documents no explicit cap; observed batches of 100 codes return 200 ok.
func (c *Client) ListSignals(ctx context.Context, productCodes []string) ([]domain.Signal, error) {
	cleaned := make([]string, 0, len(productCodes))
	for _, code := range productCodes {
		code = strings.TrimSpace(code)
		if code != "" {
			cleaned = append(cleaned, code)
		}
	}
	if len(cleaned) == 0 {
		return nil, fmt.Errorf("ListSignals: at least one product code is required")
	}

	body, err := json.Marshal(map[string]any{"productCodes": cleaned})
	if err != nil {
		return nil, err
	}

	endpoint := fmt.Sprintf("%s/api/v1/dashboard/wts/overview/ai-signals", c.infoBaseURL)
	var envelope signalsBatchEnvelope
	if err := c.postJSON(ctx, endpoint, body, &envelope); err != nil {
		return nil, err
	}

	out := make([]domain.Signal, 0, len(envelope.Result.Signals))
	for _, s := range envelope.Result.Signals {
		out = append(out, domain.Signal{
			ProductCode:          s.ProductCode,
			ReasoningDescription: s.ReasoningDescription,
		})
	}
	return out, nil
}

// Suppress unused-import warnings until later tasks fill in.

	_ = url.Parse
	_ = time.Now
)

// GetSignalDetail returns the rich Korean reasoning + news + related stocks
// payload for a single product. The productType is fixed to "STOCKS" since
// non-stock Toss assets are out of scope.
func (c *Client) GetSignalDetail(ctx context.Context, productCode string) (domain.SignalDetail, error) {
	productCode = strings.TrimSpace(productCode)
	if productCode == "" {
		return domain.SignalDetail{}, fmt.Errorf("GetSignalDetail: productCode is required")
	}

	endpoint, err := url.Parse(fmt.Sprintf("%s/api/v1/dashboard/wts/overview/ai-signals/detail", c.infoBaseURL))
	if err != nil {
		return domain.SignalDetail{}, err
	}
	q := endpoint.Query()
	q.Set("productCode", productCode)
	q.Set("productType", "STOCKS")
	endpoint.RawQuery = q.Encode()

func (c *Client) ListEventSignals(ctx context.Context, productCodes []string) ([]domain.EventSignal, error) {
	cleaned := make([]string, 0, len(productCodes))
	for _, code := range productCodes {
		code = strings.TrimSpace(code)
		if code != "" {
			cleaned = append(cleaned, code)
		}
	}
	if len(cleaned) == 0 {
		return nil, fmt.Errorf("ListEventSignals: at least one product code is required")
	}

	body, err := json.Marshal(map[string]any{"productCodes": cleaned, "filters": []string{}})
	if err != nil {
		return nil, err
	}
	endpoint := fmt.Sprintf("%s/api/v2/dashboard/wts/overview/signals", c.infoBaseURL)

	var envelope eventSignalsEnvelope
	if err := c.postJSON(ctx, endpoint, body, &envelope); err != nil {
		return nil, err
	}

	out := make([]domain.EventSignal, 0, len(envelope.Result.SignalsList))
	for _, row := range envelope.Result.SignalsList {
		out = append(out, domain.EventSignal{
			ProductCode: row.ProductCode,
			SignalLabel: row.PrimarySignal.SignalLabel,
			SignalInfo:  row.PrimarySignal.SignalInfo,
			SignalID:    row.PrimarySignal.SignalID,
			DateTime:    row.PrimarySignal.DateTime,

	}
	return out, nil

import (

// WriteSignals renders a batch of one-line signals.
func WriteSignals(w io.Writer, format Format, signals []domain.Signal) error {
	switch format {
	case FormatJSON:
		encoder := json.NewEncoder(w)
		encoder.SetIndent("", "  ")
		return encoder.Encode(signals)
	case FormatCSV:
		writer := csv.NewWriter(w)
		if err := writer.Write([]string{"product_code", "reasoning_description"}); err != nil {
			return err
		}
		for _, s := range signals {
			if err := writer.Write([]string{s.ProductCode, s.ReasoningDescription}); err != nil {
				return err
			}
		}
		writer.Flush()
		return writer.Error()
	case FormatTable:
		headers := []string{"CODE", "REASONING"}
		rows := make([][]string, 0, len(signals))
		for _, s := range signals {
			rows = append(rows, []string{s.ProductCode, s.ReasoningDescription})
		}
		return renderTable(w, headers, rows)
	default:
		return fmt.Errorf("unsupported output format: %s", format)
	}
}

## Self-review notes

- `SignalDetail` keeps the Korean text verbatim; do not translate or normalize. The point of this feature is to give LLM pipelines an idiomatic Korean explanation.
- `SignalDirection` is documented as `1 bullish / -1 bearish` based on the captured example (`signalDirection: 1` for the bullish earnings beat); 0/other values pass through.
- `ListSignals` does **not** dedup the input list — Toss returns one entry per requested code in insertion order, so callers can rely on positional matching when needed.
- `ListEventSignals` collapses the (`primarySignal`, `signals[]`) pair into one row per product. If we later need the inner detail array, expand `domain.EventSignal` to include `Signals []EventSignal` and decode there.
- CSV output is unsupported for `signals detail` (markdown-ish layout doesn't map cleanly into a single CSV row). The test for that case is intentionally **not** present; if a future caller requests it, return an explicit error message instead of partial data.
- All endpoints behave as `public` (no auth headers required), but they still send the existing session cookies if a user is logged in — the `getJSON`/`postJSON` helpers do not differentiate. This keeps the implementation simple.
